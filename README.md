# Лабораторные работы №1 (RAG) и №2 (LangGraph)

ЛР2 добавляет отдельный агентный слой `src/agent/` над исходным RAG ЛР1.
Постановка: [SPEC.md](SPEC.md), граф: [graph.mermaid](graph.mermaid),
отчёт: [report_lab2.md](report_lab2.md) и [PDF](report_lab2.pdf).
Инструкции ЛР1 ниже сохранены; запуск ЛР2 приведён в конце файла.

Проект реализует реальный локальный конвейер: PDF/Markdown/TXT → рекурсивный chunking → SentenceTransformers → персистентный Chroma → dense или BM25+dense/RRF retrieval → необязательный cross-encoder → защищённый prompt → OpenAI-compatible LLM → проверенный Pydantic JSON с цитатами. Код не привязан к ALT Linux.

## Быстрый старт (Python 3.11+)

```bash
python -m venv .venv
source .venv/bin/activate                 # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```

По умолчанию используется лёгкая multilingual E5-модель. При первом запуске она загружается из Hugging Face. Для полностью офлайн-запуска заранее поместите модель в кэш или задайте `EMBEDDING_MODEL` как путь к локальной модели.

Настройте в `.env` любой OpenAI-compatible сервер. Пример для локального Ollama:

```bash
ollama pull qwen2.5:7b
ollama serve
# значения из .env.example уже указывают на http://localhost:11434/v1
```

Ключи никогда не коммитятся: `.env` исключён из Git. Файл `.env` необязателен — безопасные локальные defaults применяются из `src/config.py`.

## Данные и индексация

Самостоятельно положите документы `.pdf`, `.md`, `.txt` в `data/` (включая подпапки), затем:

```bash
python -m src.main index
```

PDF читается постранично; ошибки отдельного файла логируются, а остальные файлы продолжают обрабатываться. Повторная индексация атомарно с точки зрения коллекции заменяет прежний корпус, поэтому удалённые документы не остаются в выдаче. Индекс хранится в `storage/`.

Размер chunk по умолчанию — 1000 символов, overlap — 150 (`CHUNK_SIZE`, `CHUNK_OVERLAP`). Это практичный баланс: слишком малые фрагменты разрывают определения и логические связи; слишком большие смешивают темы, снижают точность retrieval и расходуют context window. Рекурсивное разбиение предпочитает абзацы, затем строки, предложения и слова. Стабильный `chunk_id` образуется из источника, страницы, позиции и текста.

## Retrieval отдельно от LLM

```bash
python -m src.main search "Как обновить пакеты?" --retrieval dense --top-k 5
python -m src.main search "Как обновить пакеты?" --retrieval hybrid --top-k 5
```

JSON выдачи содержит score, source, page, chunk_id и полный текст. Hybrid — не две независимые выдачи: rankings dense и BM25 объединяются Reciprocal Rank Fusion, устойчивым к несовместимым шкалам scores.

## Вопрос к RAG

```bash
python -m src.main ask "Чем отличается Sisyphus от стабильной ветки?" --retrieval hybrid --prompt few_shot --debug
python -m src.main ask "Как работает apt?" --retrieval dense --prompt zero_shot
python -m src.main ask "Как работает apt?" --retrieval hybrid --prompt cot_structured
```

`--debug` печатает вопрос, решение LLM-router, режим, кандидатов до/после rerank, scores, context и итоговый prompt, но не конфигурацию и не секреты. `--prompt` принимает три действительно разных режима: `zero_shot` содержит только grounded-инструкции; `few_shot` добавляет три примера; `cot_structured` выполняет отдельный краткий выбор релевантных chunk IDs (без запроса длинной цепочки рассуждений), а затем формирует ответ. Итог каждого режима всё равно проверяется одной схемой `RAGAnswer`. Reranking включается `RERANK_ENABLED=true`; тогда top-N кандидатов оценивает локальный cross-encoder и оставляет `FINAL_K` с неизменёнными metadata.

Пример формы ответа (конкретные значения появятся только из вашего корпуса):

```json
{
  "answer": "Команда описана в руководстве.",
  "citations": [{"source": "guide.md", "chunk_id": "8f12ab34cd56ef78"}],
  "confidence": "high",
  "insufficient_context": false
}
```

Citation допускается только для реально переданного chunk. Достаточный ответ обязан иметь хотя бы одну citation, а недостаточный — иметь пустой список. Неверная комбинация, схема или выдуманная citation вызывает один исправляющий retry, затем явную ошибку. Пустой/слабый retrieval (`MIN_DENSE_SCORE`) возвращает детерминированный `insufficient_context=true`. Перед retrieval небольшой structured LLM-router отделяет вопросы по документам от беседы и явно посторонних тем; при `GENERAL_OR_OUT_OF_SCOPE` поиск не выполняется.

## Evaluation и anti-hallucination

После индексации и запуска LLM выполните:

```bash
python -m evaluation.evaluate --output evaluation/results.md
pytest -q
```

Скрипт прогоняет 7 вопросов через dense/hybrid и zero-shot/few-shot/cot-structured, сохраняя sources, chunk IDs и ответы. Для последнего, намеренно постороннего вопроса он сначала получает реальный no-RAG ответ той же LLM, а затем сравнивает его с grounded RAG. Ничего не предзаписано: перенесите фактические наблюдения в `report.md`. Отдельный запуск baseline доступен как `python -m src.main baseline "Какова температура поверхности Венеры?"`; он не делает retrieval и не передаёт CONTEXT. Инструкции внутри документов изолированы delimiters CONTEXT и system prompt требует считать их данными, что защищает от простой prompt injection (но не является абсолютной sandbox-защитой).

## Диагностика

* `python -m src.main --help` — все команды.
* Пустая `data/` даёт понятную ошибку и не стирает существующий индекс.
* Пустой индекс даёт пустой search/недостаточный контекст.
* Ошибка соединения при `ask` означает, что OpenAI-compatible сервер не запущен или `.env` неверен.
* Настройки моделей, порогов, top-N и final-k документированы в `.env.example`.


## Веб-интерфейс для лабораторной (Streamlit)

Веб-интерфейс повторяет обязательные этапы задания и использует **тот же** пайплайн,
что и CLI. Фактические ответы лаборатории должны основываться на найденных
документах. Отдельная шестая вкладка предоставляет чат с агентом ЛР2.

После настройки окружения и сервера из раздела «Быстрый старт» запустите:

```bash
streamlit run app.py
```

В интерфейсе шесть вкладок:

1. **Документы** - загрузить PDF/MD/TXT, проверить состав корпуса и вручную
   переиндексировать. Размер чанка и overlap отображаются из конфигурации.
   Загрузка файлов не перезаписывает существующие.
2. **Поиск** - отдельно исследовать top-N чанков до и после необязательного
   cross-encoder reranking. Доступен выбор dense и hybrid (BM25 + RRF).
3. **RAG-ответ** - задать вопрос, выбрать zero-shot/few-shot/evidence+structured,
   увидеть ответ Pydantic, реальные source/chunk_id, уверенность, список
   найденных фрагментов, блок CONTEXT и полный итоговый system/user prompt.
   Маршрутизатор можно отключать, чтобы проверить retrieval для любого вопроса.
4. **Сравнение** - прогнать **одни и те же 5–7 вопросов** в двух режимах поиска
   и трёх вариантах промптов (до 42 ответов); скачать исходную таблицу CSV.
   Маршрутизатор здесь отключён для сопоставимости экспериментов.
5. **Антигаллюцинации** - сравнить экспериментальный no-RAG baseline с
   проверенным RAG для вопроса вне корпуса. Ответ baseline **не доказательство
   галлюцинации**: заключение по нему делает исследователь.
6. **AI-агент (LangGraph)** — многотуровый чат с реальным `GraphAgent`,
   трассировкой узлов, критиком, SQLite-памятью и подтверждением действий.

### Демонстрация LangGraph в Streamlit

```bash
pip install -r requirements.txt
streamlit run app.py
```

1. На вкладке **Документы** сохраните 5–10 PDF/MD/TXT одной тематики
   (документация ALT Linux), затем нажмите **Переиндексировать корпус**.
   Загрузка сама по себе не обновляет Chroma. Агент использует этот же индекс,
   коллекцию и существующие retrieval/LLM-настройки `.env`.
2. Откройте **AI-агент (LangGraph)**. В панели **Диалоги и память** можно
   создать новый диалог, ввести `thread_id` или выбрать сохранённый.
   Сохраните ссылку с `?agent_thread=...`: после обновления страницы она
   восстанавливает выбранный поток. Источником истории служит SQLite,
   `st.session_state` хранит только выбор и значения виджетов.
3. Задайте, например, **Как обновить список пакетов ALT Linux?**
   (ответ должен присутствовать в корпусе). Проверьте `source`, `chunk_id`,
   `confidence`, `insufficient_context`. Затем задайте **А подробнее?**
   в том же диалоге. При новом `thread_id` история должна быть пустой.
4. В **Выполнение графа** показаны фактические события `AuditLog`: узлы,
   переходы, маршрут, инструменты, генерации и финальный статус. В
   **История выполнения** выберите текущий или предыдущий запуск.
   Статическая схема строится из скомпилированного графа; её Mermaid
   можно скачать. При отсутствии аудита интерфейс сообщает об этом,
   а не восстанавливает предполагаемый путь по ответу.
5. Секция **Проверка ответа (Critique)** показывает каждую генерацию,
   `accept/fix/fallback`, замечания и результат. `fix` даёт наблюдаемый
   переход `critique → generate`, максимум `I_max=3`. Замечания остаются
   в checkpoint, без текстов в JSONL-аудите. На живой LLM повторная генерация
   зависит от ответа: нельзя гарантировать `fix` конкретным вопросом.
   Для воспроизводимой проверки цикла и лимита запустите тесты ниже;
   они используют явно обозначенную mock LLM, настоящий граф и AppTest.
6. Введите **Отправь отчёт: Проверка лабораторной работы**. Граф доходит
   до настоящего `interrupt()` в `approve`; появятся аргументы действия и
   кнопки **Подтвердить / Отклонить**. До решения отправки нет.
   Обновите страницу, снова откройте вкладку и убедитесь, что подтверждение
   восстановилось. Согласие вызывает `GraphAgent.resume()` и
   `action_completed`; отказ — `action_rejected` без вызова `send_report`.
   Это локальная имитация отправки записью в SQLite, не реальное письмо.
7. Повторный rerun или обновление не выполняет LLM/отправку заново.
   Пока ожидается подтверждение, новый вопрос заблокирован. После сбоя
   без interrupt доступна отдельная кнопка **Продолжить незавершённый запуск**.

Настройки боковой панели первых пяти вкладок не меняют настройки агента.
Embedding-модель и reranker кэшируются с блокировкой inference. SQLite saver
открывается контекстным менеджером на операцию и закрывается до следующего
rerun. Межпроцессная файловая блокировка сериализует операции CLI/Streamlit
одной checkpoint-БД; при занятости интерфейс предлагает повторить операцию.
Это локальный лабораторный интерфейс без аутентификации и прав на отдельные
потоки: не используйте одну БД для независимых недоверенных пользователей.
Просмотр checkpoint-истории рассчитан на небольшое число диалогов.
Таблица трассировки ограничена последними 500 событиями запуска с уведомлением
об обрезке. В checkpoints старой версии нет полной истории замечаний критика.

```bash
pytest -q tests/test_agent_streamlit.py  # AppTest + реальный граф и SQLite, без API/embeddings
pytest -q                              # все проверки ЛР1 и ЛР2
```

Тесты проверяют citations, недостаток контекста, `fix`, лимит, согласие/отказ,
восстановление HITL новой UI-сессией, rerun без повторной отправки, изоляцию,
устаревшие кнопки, блокировку конкурентных операций и сохранение пяти вкладок.
Настоящие LLM и корпус проверяются отдельно опциональным live-тестом ниже.

Ограничения: при первом обращении к поиску загружается embedding-модель, а
при включении reranking - cross-encoder. Для ответов необходим доступный
OpenAI-compatible LLM по `LLM_BASE_URL`. В реальном корпусе должно быть
5–10 тематически связанных файлов. Вкладка сравнения не выставляет
автоматическую оценку истинности, только предоставляет наблюдения для отчёта.
Вызовы LLM внутри `cot_structured` включают отдельный выбор фрагментов;
выводить полную внутреннюю цепочку рассуждений не требуется.

**Проверка:** `pytest -q`; отдельно выполните реальный прогон с собственными
документами и LLM, приложите скриншот цитат и отказа при пустом контексте.

### Если Streamlit выводит десятки ошибок о torchvision

Файл `.streamlit/config.toml` отключает наблюдение за Python-модулями
(`server.fileWatcherType = "none"`). При запуске текстового RAG
`sentence-transformers` импортирует `transformers`, а наблюдатель Streamlit
может обратиться к ленивым атрибутам некоторых мультимодальных модулей
и получить `ModuleNotFoundError: No module named 'torchvision'`.
Это сообщение **само по себе** не означает ошибку retrieval или LLM.
Устанавливать тяжёлый `torchvision` ради наблюдателя не требуется.
После изменения исходников перезапускайте Streamlit вручную.
Если генерация ответов по-прежнему не работает, проверьте наличие индекса
и доступность LLM из `.env` отдельно: подавление этих сообщений
не исправляет ошибки соединения с LLM.

## ЛР2: LangGraph — агент с контролем потока

Требуется Python 3.11+. Проверено на Python 3.12 с `langgraph==1.2.21`,
`langgraph-checkpoint-sqlite==3.1.0`, `langchain-core==1.8.0`.
Установка та же: `pip install -r requirements.txt`, `cp .env.example .env`.
Все команды выполняются **из корня рабочей копии AI-lab2**.
Для factual-вопросов положите документацию ALT Linux в `data/`, выполните
`python -m src.main index` и настройте доступную LLM через существующие
`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Индекс ЛР1 используется напрямую.

```bash
source .venv/bin/activate
python -m src.agent.cli ask "Как обновить список пакетов ALT Linux?" --thread-id lab2 --trace
python -m src.agent.cli ask "А подробнее?" --thread-id lab2 --trace
python -m src.agent.cli status --thread-id lab2
```

`--thread-id` сохраняет диалог между процессами; без него `ask` создаёт UUID
и возвращает его в JSON. Для нового диалога задайте другой идентификатор.
Идентификатор: 1–64 латинских буквы, цифры, `_`, `-`.
Явные короткие уточнения (`А ...`, `И ...`, `Подробнее`, `Поясни`, `Уточни`)
получают предыдущий пользовательский вопрос как контекст поиска; документы
каждый раз извлекаются заново. Полная история хранится в checkpoint, но не
подмешивается целиком к доказательствам. Неявные местоименные ссылки могут
потребовать полного вопроса.

Без LLM, embedding-модели и корпуса работают точные команды:

```bash
python -m src.agent.cli ask "Привет" --thread-id greeting
python -m src.agent.cli ask "Сколько времени?" --thread-id clock
python -m src.agent.cli ask "Отправь отчёт: Проверка документации ALT Linux" --thread-id report --trace
# Граф приостановлен. Эта команда запускается отдельным процессом:
python -m src.agent.cli status --thread-id report
python -m src.agent.cli resume --thread-id report --decision yes --trace
```

Для отказа создайте новый запрос отчёта и выполните:

```bash
python -m src.agent.cli ask "Отправь отчёт: Проверка отказа" --thread-id reject
python -m src.agent.cli resume --thread-id reject --decision no --trace
```

`resume` принимает только `yes/no`; необязательный `--action-id` проверяет ID
из запроса подтверждения. Чужой ID отклоняет действие. Ни строка `"true"`,
ни произвольный текст не считается подтверждением в программном API.
При ожидающем HITL новый `ask` запрещён, пока пользователь не примет решение.
Повторный `resume` завершённого запуска возвращает ошибку без вызова инструмента.
`continue --thread-id ...` восстанавливает незавершённый запуск после сбоя;
эта команда не обходит HITL.

`send_report` **имитирует** отправку записью в `storage/agent_reports.sqlite`;
таблица `reports` содержит `action_id`, время, текст. Сеть и shell не вызываются.
Запись и защита от дубликатов составляют одну SQLite-транзакцию. Отказ не
создаёт записи или файла отчётов. Путь и получатель не задаются пользовательским
текстом. Допускается только явная команда «Отправь отчёт: текст» до 4000 символов.

### Граф, структура результата и лимит

`StateGraph`: `route → retrieve → generate → critique → finalize`.
`fix` возвращает в `generate`, `accept` и `fallback` ведут в `finalize`.
Ветки инструментов: `route → call_tools → finalize` (время) и
`route → approve [interrupt] → call_side_effect → finalize` (отчёт).
Отказ в approve ведёт сразу в finalize. Приветствие и отказ не запускают retrieval.
Точная схема с условиями находится в `graph.mermaid`.

`iterations` — число входов в `generate` **текущего запроса**, включая ошибки
LLM, максимум **3**. Маршрутизация и семантический критик не увеличивают счётчик;
при полном цикле возможно до 7 LLM-вызовов: 1 классификация + 3 генерации +
3 проверки. Структура/цитаты проверяются локально до семантического критика.
Последний проверяет релевантность и каждое фактическое утверждение по тексту
процитированных чанков. `fix` передаёт замечания следующей генерации.
Ошибка критика даёт безопасный fallback. Исчерпание исправлений даёт
`iteration_limit`, `insufficient_context=true`, `citations=[]`.

Успешный CLI-вызов печатает JSON-конверт:

```json
{
  "thread_id": "lab2",
  "run_id": "opaque-uuid",
  "status": "completed",
  "result": {
    "answer": "...",
    "citations": [],
    "confidence": "low",
    "insufficient_context": true,
    "status": "insufficient_context",
    "thread_id": "lab2",
    "run_id": "opaque-uuid",
    "iterations": 0,
    "tool_result": null
  },
  "interrupt": null
}
```

При HITL `status="interrupted"`, `result=null`, а `interrupt` содержит имя
инструмента, `action_id`, аргументы и вопрос подтверждения. До resume итогового
ответа нет. `result.status`: `answered`, `insufficient_context`, `iteration_limit`,
`smalltalk`, `time`, `refused`, `action_completed`, `action_rejected`, `error`.
Для служебных маршрутов цитаты пусты, а `insufficient_context=false` обозначает
служебное сообщение; оценивать наличие документальных фактов следует только
при `status="answered"`. Ошибка retrieval/генерации даёт `error` и безопасный
ответ с `insufficient_context=true`. Ошибка классификации даёт `refused`.

История `messages` использует reducer `add_messages`; остальные поля — last-value.
Узел `route` очищает retrieved, draft, critique, iterations, approved,
pending_action, tool_result, error, final при каждом новом запросе.
SQLite checkpointer, а не Python-переменная или Streamlit, хранит историю и паузу.
Приложение CLI рассчитано на последовательные команды одного thread_id.

### Настройки и логи ЛР2

Настройки `AGENT_CHECKPOINT_DB`, `AGENT_REPORTS_DB`, `AGENT_LOG_PATH`,
`AGENT_TIMEZONE` приведены в `.env.example`. По умолчанию время — Europe/Moscow.
Checkpoint и отчёты исключены из Git, существующий Chroma остаётся в своей коллекции.
JSONL `logs/graph_run.jsonl` содержит фактические события исполнения: thread/run,
узел, переход, вызов инструмента, решение критика, номер генерации, HITL и статус.
`--trace` дублирует эти события в stderr; итоговый JSON остаётся в stdout.
В аудит не попадают вопросы, документы, текст отчёта, prompts, замечания LLM
и тела исключений. Диалог и документы сохраняются только в локальном checkpoint.

### Проверки и воспроизводимая демонстрация

```bash
pytest -q -m "not integration"  # unit, включая все прежние тесты ЛР1
pytest -q -m "integration and not live"  # настоящий Chroma + отдельные CLI-процессы
pytest -q                     # вместе; внешний live-тест пропускается по умолчанию
python -m evaluation.demo_agent --output-dir work/agent-demo
```

Демо выполняет 7 сценариев (приветствие, отказ, время, factual с исправлением,
недостаток контекста, согласие и отказ от отчёта) через **реальный LangGraph**,
но с **явными фикстурами LLM и корпуса**. Это демонстрация управления потоком,
не измерение качества ALT Linux RAG. Строки аудита помечены `mode="fixture"`;
`work/agent-demo/results.json` содержит полученные результаты. Приложенный аудит
может также содержать `mode="live"` для реальных безопасных CLI-инструментов.
Никаких заранее записанных логов сценарий не копирует: они формируются узлами.

Для полной интеграции сначала проиндексируйте настоящий корпус и запустите LLM:

```bash
RUN_LIVE_AGENT=1 AGENT_LIVE_QUESTION="Как обновить список пакетов ALT Linux?" \
  pytest -q -m live
```

Вопрос должен иметь ответ в вашем корпусе. Live-тест проверяет реальную генерацию
и принадлежность цитат полученным чанкам. Доступность LLM/embedding-моделей и
пользовательский корпус не заменяются фикстурами в этом тесте.
Семантическая критика другой инструкцией той же LLM снижает риск неподтверждённых
ответов, но не является формальным доказательством истинности или полной защитой
от prompt injection. Фактическая оценка на корпусе описывается отдельно в отчёте.
